# E + R5a + R2: eval hardening, mix clarity, F5 chunk ownership

**Date:** 2026-10-08
**Status:** The user approved the scope in chat on 2026-10-08. They waived
per-stage review until all three phases are built and the next eval set is
ready to render, so the design decisions below are recorded as rulings in
`docs/superpowers/notes/2026-10-e-r5a-r2-deferred-minors.md`.
**Program:** `2026-10-06-generation-quality-roadmap.md`, "Execution order after the R1 evaluation".

## Why

The R1 blind A/B was a null result: 5 R1 wins, 6 baseline wins and 10 ties.
The listener's notes and a stem check point at two problems, present in both
arms:

1. **The music masks the voice and swells suddenly in pauses.**
2. **The F5 voice still sounds somewhat robotic, with stalls and glitches.**

This round fixes both, behind flags. It also makes the A/B harness able to
tell the fixes apart: same scripts in every arm, shuffled pairs and "lean"
answers.

**Success:** All three phases are implemented with unit tests. Flags default
OFF for every golden-path change; the loudness bug fix is ON with a
kill-switch. A real-model smoke render of each new path passes, and R2's
peak memory is measured and kept within today's. The final deliverable is a
ready-to-render eval plan, with the exact commands per arm. Rendering it
waits for the user's go-ahead.

## Part E: eval hardening

### E1. Render-only mode

- **Extract the render half of `auto_generate.run()`** into
  `render_script(script, *, config, background_label, background_path,
  pipeline, progress_cb=None, **pipeline_kwargs) -> RenderResult`.
  - It covers: content profile → generate kwargs → `pipeline.generate` →
    duration measurement → `<name>.script.txt` + `<name>.meta.json`.
  - `run()` calls it, and its behaviour and meta keys are unchanged.
  - The corpus append and the recent-backgrounds bookkeeping stay in `run()`.
- **`scripts/eval_genres.py --scripts-from <config_dir>`.** `<config_dir>` is
  an earlier run's config directory, e.g. `var/eval/x/base/eval`.
  - For every case directory that holds `*.script.txt` and `*.meta.json`, it
    renders that script through `render_script`. It reuses the source meta's
    `genre`, `voice`, `background` and `background_path`, plus the case's
    `seed` and `band` from the source run's `results.json`.
  - No LLM model loads.
  - Metrics and stems work as in a normal run.
  - The new meta adds `"rendered_from": "<source case dir>"`.
- **`--configs` becomes optional** when `--scripts-from` is given. The output
  config name comes from `--name` (default `eval`).
- **A missing background file is an error for that case**, not a silent
  re-pick. A different bed would invalidate the comparison.
- **TTS cache key gains an env fingerprint.** `compute_cache_key` takes
  `env_fingerprint: str`. The pipeline passes a stable string of every set
  `MOODSCAPE_F5_*` and `MOODSCAPE_CHATTERBOX_*` variable (sorted
  `KEY=VALUE` pairs). Today the key ignores flags such as chunking, nfe and
  ref-pad, so an R2 arm would hit the base arm's cached voice.
  - Mix-only arms (R5a) keep hitting the cache: same script, voice, speed and
    seed, no TTS env change. So they skip F5 entirely. That is what makes
    four mix arms cheap.

### E2. Shuffled pair order and lean answers

- **`build_pairs` shuffles the pair order** with the same seeded RNG before
  assigning ids, so a case's three excerpts are not consecutive.
  `.key.json` still maps id → arm, case and position.
- **The sheet accepts `leanA` / `leanB`**, case-insensitive, besides `A`,
  `B` and `same`.
  - The **SHIP / NO-SHIP verdict is unchanged**: leans count as ties.
  - `score()` additionally reports:
    - `challenger_leans` and `baseline_leans`;
    - `weighted_rate = (cw + 0.5·cl) / (cw + bw + 0.5·(cl + bl))`;
    - `lean_inclusive_p`, a sign test counting leans as wins.

  All three are reported only.
- `ab_score.py` prints them.
- **`ab_export.py --positions start,middle`** (default: all three) selects
  which excerpts to cut. It keeps rounds near 14 pairs.

### E3. Tracked listening page and answer import

- **`scripts/ab_listen_page.py`** is promoted from
  `var/eval/r1/make_listen_page.py`. It takes multiple rounds plus optional
  "how to listen" text per round.
  - The choices are A / lean A / same / lean B / B.
  - The Qwen section is dropped.
  - The localStorage key comes from the page title, so pages don't share
    answers.
- **`scripts/ab_import_answers.py <answers.json> <round_name=ab_dir> ...`**
  writes each round's answers into its `sheet.csv` (pair, choice, reason).
  It replaces the hand-written import from 2026-10-08.

## Part R5a: mix clarity and loudness

### R5a-1. Loudness convention fix (bug fix: ON, kill-switch)

- **The bug:** `export_audio` normalises a mono mix to −16 LUFS as measured
  on one channel. Played on two channels it is about −13 LUFS, which is
  3 LU hot. The R1 eval confirmed this.
- **The fix**, under `MOODSCAPE_LOUDNESS_DUAL_MONO` (default `1`):
  - The pipeline's target becomes the playback loudness per content type:
    meditation −16, sleep story −18. It comes from a new profile key
    `export_lufs`.
  - `export_audio(..., target_lufs, mono_playback_offset_db=3.01)` subtracts
    the offset when the audio is mono and the flag is on.
  - Stereo output is unchanged.
  - `MOODSCAPE_LOUDNESS_DUAL_MONO=0` restores −16 for every content type
    with no mono offset.
- **Verification:** the eval's `integrated_lufs_dual_mono` reads −16 ± 0.5
  for a meditation.
- **Untouched:** `calculate_loudness_gain`'s −18 → −21 mono quirk (the voice
  normalisation before the mix). Changing it would shift the
  voice-to-bed balance.

### R5a-2. Bounded bed rise in pauses (flag, default OFF)

- **Today:** after each phrase the bed climbs the whole duck depth (about
  16 dB) plus a 1.5 dB lift on a 1.5 s S-curve, even in a 2 s pause. That
  is the "music gets loud suddenly".
- **New:** `MOODSCAPE_BED_RISE_LIMIT=1` applies an asymmetric slew limiter to
  the *script* gain curve. Rises are capped at
  `MOODSCAPE_BED_RISE_DB_PER_SEC` (default 3.0); falls are untouched.
  - The pre-descent before each phrase is unchanged.
  - The rise is also capped at `MOODSCAPE_BED_RISE_MAX_DB` (default 12.0)
    above the speech duck level, and `lift_db` is forced to 0.
  - Net effect: a 2 s pause rises about 6 dB instead of about 17. A long
    pause plateaus 4 dB under today's pause level.
- **Implementation:**
  - Decimate the gain curve to a 100 Hz control rate.
  - Run the slew limiter as a short Python loop (about 60k steps for
    10 min).
  - Linearly interpolate back.
  - Combine with the reactive safety net as today.
- **Scope:** both the fullband and the multiband (spectral) duck paths, and
  both content types. The sleep profile's slower release still applies
  first.

### R5a-3. Duck-shape arms for the A/B (env only)

- **The spectral duck** already exists: `MOODSCAPE_SPECTRAL_DUCK=1`.
- **The shallower duck:** new env overrides `MOODSCAPE_BED_SPEECH_OFFSET_LU`
  and `MOODSCAPE_BED_PAUSE_OFFSET_LU` replace the content profile's
  calibration offsets.
  - When either is set, `calibrate_music_bed`'s duck clamp widens from
    (−20, −10) to (−20, −4).
  - When neither is set, nothing changes. That protects sleep stories,
    whose 22/16 profile is clamped to a 10 dB duck today; that existing
    quirk is noted, not fixed, here.
  - The A/B "shallow" arm uses speech 28 / pause 20. That is an 8 dB duck,
    bed 2.5 dB louder under speech and 5.5 dB quieter in pauses: less
    pumping, quieter overall.

## Part R2: F5 chunk ownership and per-chunk speech QA

### R2-0. Memory measurement first

Before anything else, measure F5 on one short-band script under the RAM
lock: the whole-pipeline peak footprint and the TTS-stage footprint
(`/usr/bin/time -l` plus `torch.mps.current_allocated_memory` /
`driver_allocated_memory` logged per chunk).

| If F5's own driver allocation… | Then |
|---|---|
| grows across chunks (cache build-up) | R2 calls `torch.mps.empty_cache()` after each chunk and before loading Whisper |
| does not grow | Whisper QA runs after synthesis with F5 still loaded (Whisper turbo fp16 ≈ 1.6 GB) only if the measured headroom allows; otherwise QA runs after the TTS stage unloads, and failing chunks are re-rendered in a second, short F5 load |

R2-4 implements the measured branch. The chosen branch and the numbers are
recorded in the findings note.

### R2-1. Breath-group chunker (pure functions)

New module: `core/f5_tts/chunking.py`.

- `f5_char_budget(ref_text, ref_duration_sec, speed) -> int` mirrors
  upstream's `max_chars` formula (f5-tts 1.1.22 `infer_process`):
  `int(len(ref_text.encode()) / ref_dur * (22 − ref_dur) * speed)`.
  - `ref_dur` is the **conditioned** (ref-padded) reference duration.
  - A 0.9 safety factor applies.
- `breath_groups(text, budget) -> list[BreathGroup(text, gap_after_sec)]`:
  - Splits on sentence ends first, then `; :`, then `,`, then em-dash.
  - Greedily packs whole units up to the budget, and only splits a
    single over-budget unit at the last space.
  - **Guarantee:** for every group,
    `f5_tts.infer.utils_infer.chunk_text(group, budget/0.9)` returns exactly
    `[group]`. Upstream never re-splits; a unit test asserts it against the
    real `chunk_text`.
- **Gap after a group**, from its final punctuation:
  - sentence end 0.45 s;
  - `; :` 0.35 s;
  - `,` and em-dash 0.20 s;
  - forced space split 0.0 s.

  Env-tunable: `MOODSCAPE_F5_GAP_SENTENCE` / `_CLAUSE` / `_COMMA`. These
  replace upstream's fixed 0.15 s crossfade. The segment's final group has
  no gap, because the script's own `[pause]` follows.
- **Fragments are left as they are.** Short-phrase pacing still triggers on
  a group of 12 or fewer non-space characters.

### R2-2. Engine integration (flag `MOODSCAPE_F5_CHUNKING=1`, default OFF)

- With the flag on, `F5Engine.synthesize` splits each speech segment into
  breath groups.
  - Each group is one `infer` call with its own seed
    (`seed + speech_idx`, counted per group) and its own trailing-silence
    trim.
  - Groups are joined with room tone of `gap_after_sec`, and the activity
    mask stays false in the gaps.
- With the flag off, behaviour is byte-identical to today.
- The breath groups and their timings are kept on the engine as
  `self.last_chunks: list[ChunkRecord(text, audio, seed, start_sample)]`
  for R2-3/R2-4.

### R2-3. Per-chunk QA (engine-agnostic)

New module: `core/speech_qa.py`, with no F5 imports.

- `chunk_signal_checks(audio, sr, text) -> list[str]` returns failure codes
  and needs no model:
  - `INTERNAL_GAP`: a silent run of 0.6 s or more with voice on both sides
    (`speech_metrics` framing);
  - `TRUNCATED`: speech ends within 50 ms of the buffer end while text
    remains, measured as audio shorter than 35% of the expected
    `chars × median_sec_per_char`.
- `rate_outliers(records) -> set[int]`: chunks whose seconds-per-character
  is below 0.6× or above 1.7× the render's median. Chunks of 12 or fewer
  characters are skipped (pacing makes them slow on purpose).
- `transcript_check(audio, sr, text, transcriber) -> (code | None, cer)`:
  - `HIGH_CER` when CER > 0.20 on the normalised text.
  - It uses `core.eval.speech_metrics.WhisperTranscriber` and `cer`, already
    shipped.
- `score_candidate(codes, cer, rate_dev)`: lower is better. It orders by
  failure count, then CER, then deviation from the median rate.

### R2-4. Best-of-3 re-render (flag `MOODSCAPE_F5_CHUNK_QA=1`, default OFF; needs CHUNKING)

1. After all groups are synthesised, run the signal checks and the rate
   outliers. Then run the Whisper check on every chunk, using the
   memory-safe order from R2-0.
2. Each failing chunk gets up to 2 more candidates with seeds
   `seed + 10_000·k + idx`, at the **same NFE** as the original.
3. Keep the best-scoring candidate, and splice it back at its start sample.
   Later chunks shift, so the join is rebuilt rather than patched in place.
4. Log a per-render QA summary (chunks, failures by code, re-renders, chunks
   still failing). Return it via `self.last_qa`, and the pipeline copies it
   into `meta.json` under `"speech_qa"`.
5. A chunk that fails all 3 attempts ships its best attempt. QA never fails
   a job, matching the advisory philosophy.

- **Cost bound:** at most 2 extra infers per failing chunk, plus one Whisper
  pass. Expected failure rate is 10–20% of chunks, adding about 20–40%
  TTS time.

### R2-5. A/B arm for warmth

`MOODSCAPE_F5_CFG=1.2` already exists. The R2 cfg arm is
`CHUNKING=1 CHUNK_QA=1 F5_CFG=1.2`. The env fingerprint makes it a cache
miss.

## The eval set to build (rendered only after the user's go-ahead)

**Genres:** 7 short-band cases.
- anxiety_relief, body_scan, box_breathing, deep_sleep, self_compassion,
  yoga_nidra and panic_sos.
- deep_sleep is a `sleep_story` pack, so the sleep loudness and bed are
  heard.
- panic_sos drew the "music gets loud suddenly" note.
- Seeds come from the R1 testset values.

**Arms**, all on the same scripts:

| Arm | How | Env | F5 render? |
|---|---|---|---|
| `base` | full run (LLM + render) | none | yes |
| `rise` | `--scripts-from base` | `BED_RISE_LIMIT=1` | no (cache) |
| `rise_spectral` | `--scripts-from base` | + `SPECTRAL_DUCK=1` | no |
| `rise_shallow` | `--scripts-from base` | + `BED_SPEECH_OFFSET_LU=28 BED_PAUSE_OFFSET_LU=20` | no |
| `rise_r2` | `--scripts-from base` | `BED_RISE_LIMIT=1 F5_CHUNKING=1 F5_CHUNK_QA=1` | yes |
| `rise_r2_cfg` | `--scripts-from base` | + `F5_CFG=1.2` | yes |

**Rounds** (2 excerpts per case, start and middle, so 14 pairs a round):

| Round | Question | Pairs |
|---|---|---|
| A | Does the bounded rise help? | base vs rise |
| B | Which duck shape? | rise_spectral vs rise_shallow |
| C | Does R2 fix the voice? | rise vs rise_r2 |
| D | Warmer? | rise_r2 vs rise_r2_cfg |

That is about 56 pairs and 70 minutes of listening.

## Protected invariants

All of these are kept:
- the FATAL/ADVISORY split;
- writer/judge independence;
- `<problems>` stripping;
- `unload()` after each LLM stage;
- no pedalboard `Limiter`;
- the upload stem-separation skip;
- `MOODSCAPE_ADAPTIVE_BED`.

R2 adds models only in the order R2-0 measures.

- Fixing the sleep-story duck-clamp quirk (noted only).
