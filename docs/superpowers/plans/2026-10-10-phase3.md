# Phase 3 Implementation Plan (content, timing, content check, memory, eval)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Remove the medical and child wording our own rules produce, and
block it globally. Add the F5 lead-in trim and duration control. Add an LLM
content check. Cut the pipeline's memory peak. Then build the R3 eval.

**Architecture:**
- **Content:** the linter, the planner and the safety-rules doc (Part C).
- **Timing:** the F5 `_infer_chunk` (T1); `script_gen/duration.py` plus
  `generate_script` (T2).
- **Content check:** a new `script_gen/content_check.py` called from
  `generate_script` (K).
- **Memory:** the pipeline/mixer stages (M).
- **Eval tooling:** `scripts/ab_review.py` and `scripts/ab_chain.py` (E2).

**Tech Stack:** Python 3.11, numpy, re, f5-tts 1.1.22, Ollama-backed
`ScriptEngine.complete(system, user, *, max_tokens, sampling) -> str`,
unittest/pytest.

**Spec:** `docs/superpowers/specs/2026-10-10-phase3-design.md`

## Global Constraints

- **Commits:** commit to `dev` and never push. Use conventional commits
  ending `Co-Authored-By: <model> <noreply@anthropic.com>`.
- **Tests:** `.venv/bin/python -m pytest tests/unit/ -q` stays green (936 at
  start). Put new test classes ABOVE any `if __name__ == "__main__":` guard.
  Unit tests never load real models. Tests that run `scripts/*.py main()`
  wrap it in `mock.patch.dict(os.environ, {}, clear=False)`.
- **Real models:** only the controller loads them, under
  `var/heavy-model.lock`.
- **Flags:**
  - `MOODSCAPE_F5_TRIM_LEADIN` defaults to 0;
  - `MOODSCAPE_DURATION_CONTROL` defaults to 1 (kill-switch);
  - `MOODSCAPE_CONTENT_CHECK` defaults to 1 (kill-switch).
  - TTS-affecting env vars must start with `MOODSCAPE_F5_` (cache
    fingerprint).
- **Flags off means unchanged:** with every new flag at its "off" value,
  audio output is identical to today.
- **Invariants:**
  - the FATAL/ADVISORY split;
  - writer/judge independence;
  - `<problems>` stripping;
  - `unload()` after each LLM stage (K runs before the judge unload in
    `generate_script`'s `finally`);
  - no pedalboard `Limiter`.
- **Content rule (user, 2026-10-10):** scripts never mention illness,
  medical conditions, pregnancy, diagnoses, medication or surgery, and never
  picture a child, children, a baby or a younger self.

## Review Focus

1. **False positives in SENSITIVE_TOPIC.** These must NOT match:
   "childhood", "heart" ("hand on your heart"), "medical" alone, "kidney
   beans", "babysit"? It must match "your inner child", "Children play",
   "a baby", "if you are pregnant". Test in Task 2.
2. **A breathwork script using the old medical disclaimer** must now FAIL
   (SENSITIVE_TOPIC), not pass MISSING_DISCLAIMER. The new gentle line
   must pass. Test in Task 1/2.
3. **Pause scaling on a script with tiny pauses** keeps every pause at
   ≥ 1.0 s and rounds to 0.5 s. A factor outside [0.85, 1.15] is clamped.
   A script with no pauses comes back unchanged. Test in Task 5.
4. **Content-check JSON that is malformed twice** skips the check with a
   warning and never fails the job. A finding whose quote isn't in the
   script is dropped. Test in Task 7.
5. **The lead-in trim on a chunk that starts with speech** (no lead-in) is
   unchanged. On an all-silent chunk it returns the input (no crash, no empty
   array). Test in Task 4.

### Task 4: Lead-in trim (T1, flag OFF)

**Files:**
- `core/f5_tts/engine.py`: a new module-level
  `_trim_leading_silence(arr, sr, *, lead_ms, floor_db) -> np.ndarray`,
  applied in `_infer_chunk` right after `_trim_trailing_silence` when
  `os.environ.get("MOODSCAPE_F5_TRIM_LEADIN", "0") == "1"`.
- Test: `tests/unit/test_f5_leadin.py`.

**Behaviour:**
- Frame RMS over 10 ms frames, in dB.
- `peak = max(frame dB)`. The first frame ≥ `peak + floor_db` (floor_db
  defaults to −35, `MOODSCAPE_F5_TRIM_LEADIN_DB`) is the onset.
- Keep `lead_ms` (default 60, `MOODSCAPE_F5_TRIM_LEADIN_LEAD_MS`) before the
  onset.
- Apply a 10 ms linear fade-in at the new start.
- Return the input unchanged if there is no frame above the threshold, the
  onset is within `lead_ms`, or the array is shorter than 2 frames.

**Tests:**
- 1.5 s of −55 dB noise, then a 1 s tone at −10 dB → output length ≈
  1.06 s ± 10 ms, and the first sample's magnitude is ≤ that of the
  original sample at the same position.
- A tone from t=0 → unchanged (array equal).
- All zeros → unchanged.
- Flag off → `_infer_chunk` output equals the old path. Use a fake model as
  in `tests/unit/test_f5_engine_chunking.py` and reuse its helpers.
- Flag on → leading near-silence is removed in the synthesized output for a
  fake model that returns noise+tone.

- [ ] TDD → implement → full suite → commit `feat(f5): MOODSCAPE_F5_TRIM_LEADIN trims the ref-pad lead-in before each chunk (default off)`

### Task 6: Duration control in `generate_script` (T2, ON with kill-switch)

**Files:**
- `core/auto_generate.py` `generate_script` loop (~lines 425–500), plus
  `ScriptOutcome` (new field
  `duration_control: dict = field(default_factory=dict)`), and `run()`'s
  meta (`"duration_control"`).
- Test: `tests/unit/test_auto_generate.py`. Reuse the FakeEngine
  scripted-response pattern already used for repair tests.

**Behaviour:** gated by `os.environ.get("MOODSCAPE_DURATION_CONTROL", "1") != "0"`.

1. When `fatal` is empty and the estimate is outside
   `[min*0.85, max*1.15]`, and `repairs_used < max_repairs` and no length
   repair has happened yet: build a `Violation("DURATION_OUT_OF_WINDOW", ADVISORY, msg)`.
   - `msg = f"Estimated runtime {est:.0f}s; target {min:.0f}-{max:.0f}s. Rewrite to about {target_words} words of speech (keep the same [pause] marker style), aiming for {target_mid:.0f}s."`
   - `target_words = round(current_words * target_mid / est)`.
   - `target_mid = (min + max) / 2`.
   - Call `repair(...)` with `[that violation]` plus the existing
     STYLE_CODES violations.
   - `repairs_used += 1`, set `length_repair=True`, and `continue` the loop
     (re-estimate, re-lint).
2. When `fatal` is empty and the estimate is still outside `[min, max]`
   (strict): compute the factor needed so that the total *pause* seconds
   change moves the estimate toward the nearest window edge. Apply
   `scale_pauses` (clamped), re-estimate, and record `pause_scale=factor`.
   Re-run `check()` on the scaled script so the returned violations match
   it.
   - Implementation hint: estimate speech-only seconds as
     `est − total_pause_sec(script)`. Add a helper `total_pause_sec(script)`
     in duration.py, plus a test for it.
3. `ScriptOutcome.duration_control = {"length_repair": bool, "pause_scale": float}`
   (1.0 when not applied).

**Tests:**
- Fake judge responses: an over-long script (estimate ≫ max) → exactly one
  length repair is requested, and its message contains "Rewrite to about".
- A script just 10% over → no repair, but pause scaling is applied and the
  outcome's `pause_scale` < 1.
- `MOODSCAPE_DURATION_CONTROL=0` → neither happens.
- The repair budget is respected: with `max_repairs=0`, no length repair.
- A fatal violation still takes priority: length repair happens only after
  fatal violations are cleared.

- [ ] TDD → implement → full suite → commit `feat(auto_generate): duration control — one length repair, then bounded pause scaling (kill-switch MOODSCAPE_DURATION_CONTROL=0)`

### Task 7: LLM content check (K, ON with kill-switch)

**Files:**
- New: `core/script_gen/content_check.py`.
- Modify: `core/auto_generate.py` `generate_script`. Call it on the judge
  engine when the lint loop is about to return. Feed findings into the
  repair path, then return them as ADVISORY.
- Modify: `core/script_gen/__init__.py` (exports).
- Test: `tests/unit/test_content_check.py`, plus an integration test in
  `test_auto_generate.py`.

**Interfaces:**

```python
CONTENT_CODE = "SENSITIVE_CONTENT"
def content_findings(engine, script: str, *, genre: str, max_tokens: int = 800, sampling=None) -> list[dict] | None
    # returns [{"quote","reason"}] (quotes verified present in the script, case/whitespace-insensitive),
    # [] when clean, None when the check could not run (2 malformed JSON replies or engine error) — caller logs + skips
def findings_to_violations(findings, *, severity) -> list[Violation]
```

**Prompt:** a fixed system prompt listing the categories from spec K1. Ask
for ONLY a JSON array, `[]` when clean. The user message holds the script
(tags stripped) plus `genre: <slug>`. Parse the first `[...]` block. Grief
packs (slug contains `grief` or `loss`) may mention loss and death; tell the
model so.

**Integration:** gated by `MOODSCAPE_CONTENT_CHECK != "0"`. When the loop
reaches a no-fatal state:
- **First time:** run `content_findings`. If there are findings and budget
  remains, repair with `findings_to_violations(..., severity=FATAL)` plus
  STYLE_CODES, `repairs_used += 1`, `continue`.
- **On the next no-fatal state:** run the check again. If there are still
  findings and no budget is left, append them to the returned violations as
  ADVISORY and return.
- **Ordering:** run it at most twice per script, and after duration control
  so that a length rewrite gets checked too.
- Record in `ScriptOutcome` and meta:
  `"content_check": {"ran": bool, "findings_first": n, "findings_final": n}`.

**Tests:**
- clean `[]` → no repair;
- one finding → one repair with SENSITIVE_CONTENT FATAL, then clean;
- a finding whose quote is absent → dropped;
- malformed twice → None, logged, render continues;
- budget exhausted → returned as ADVISORY, no exception;
- kill-switch → never called;
- the judge engine is not unloaded before the check (the existing `finally`
  ordering).

- [ ] TDD → implement → full suite → commit `feat(script_gen): LLM content check for sensitive wording (repairs, ADVISORY after budget; kill-switch MOODSCAPE_CONTENT_CHECK=0)`

### Task 10: Eval tooling (E2a)

**Files:**

**Eval spec TOML shape:**

```toml
title = "MoodScape R3 eval (Oct 2026)"
testset = "var/eval/r3/testset.toml"
out = "var/eval/r3"
configs = "eval=ollama:qwen3.8:27b|ollama:gemma4:31b"
positions = "start,middle"
[[arms]]
name = "base"            # first arm = full LLM run
desc = "today's defaults"
env = {}
[[arms]]
name = "spectral"
desc = "+ spectral duck"
env = { MOODSCAPE_SPECTRAL_DUCK = "1" }
cached = true            # expects TTS cache hit (warning if not)
from = "base"            # scripts-from arm (default base)
[[rounds]]
id = "abA"
name = "Round A: duck"
a = "base"
b = "spectral"
how = "Same voice and script ... "
```

**The generated chain must:**
- hold the lock and keep the trap/cleanup;
- run base, then the other arms in file order;
- use `--scripts-from <out>/<from>/eval`;
- run the cache-hit warning check for `cached = true` arms;
- export with `--allow-missing --positions`;
- build the page from the existing sheets;
- run `ab_review.py`.

`ab_review.py` writes REVIEW.md and injects the summary into listen.html, as
`make_review.py` does today (port its tested behaviour, keyed by the spec).

**Tests:**
- the generated script contains the expected commands and env per arm and
  passes `zsh -n`;
- the review generator, on fixture dirs, renders tables, warns on a missing
  arm, and the injection is idempotent.
